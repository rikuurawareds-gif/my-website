# ナレッジベース（アフィリエイト運用の知識）

担当エージェントは、運用・提案・設計に関わる判断の前にここを読む。実際の提案資料や運用事例から学んだことを、**社名・媒体名・個別の数字を伏せて一般化**して蓄積する。

| ファイル | 中身 |
|---|---|
| `owner-insights.md` | **オーナーの見立て（最優先）**: 誰に売るか、決裁者と断る理由、ASP・メディアの力学、料金の感触 |
| `operations-playbook.md` | アフィリエイト運用の考え方（KPI、チャネル、打ち手、媒体の分類、テストの判定、新規開拓、季節性） |
| `proposal-playbook.md` | 広告主への提案の組み立て方、料金・承認方式・委任範囲・契約条件の型、よくある質問 |
| `workload-benchmarks.md` | 広告主側の運用工数の実データ（業務ごとの時間と、移管後に残る作業） |
| `metrics-dictionary.md` | 指標辞書（ファネルの段階、質・収益性・掲載の指標の式と分母） |
| `report-playbook.md` | 定例・月次レポートの型（構成、要因分解、外部環境、着地見込み、文章ルール、品質管理、判断の記録） |

## ナレッジの層（入れ方のルール）
古い単価や終わった方針を「正」として覚えないように、層を分ける。
1. **ルール層**（常に正）: `metrics-dictionary.md`、`report-playbook.md` の品質管理と文章ルール、`../CLAUDE.md`
2. **お手本層**（型を学ぶ。数字は参考）: `operations-playbook.md`、`proposal-playbook.md`、`report-playbook.md` の構成と要因分解
3. **事例層**（日付つきで検索する）: Drive の読み込みノートと元資料
4. **入れないもの**: ネット単価・マージン・粗利の実数、ID・パスワード、人物の評価

## まだ足りないもの（資料が来たら優先して取り込む）
- 業種が人材以外の事例（EC、美容・健康、金融、通信）。表記・承認・成果地点がまったく違う
- 軽い運用（窓口が数社）の広告主の工数
- 停止案件の総括（何が効いて、なぜ止まったか）
- 施策 → 結果 → 学び のログ、定例ごとの判断メモ

## 新しい資料を取り込む手順
1. オーナーが元資料を上のDriveフォルダに入れ、PMに「取り込んで」と伝える。
2. PMが全ページを読み、事例ノート（数字・媒体名あり）をDriveに作る。
3. 一般化した学びを上の3ファイルに追記する。すでにある内容と食い違う場合は、両方の条件（業種・規模）を書いて併記し、どちらかを消さない。
4. 学びが商品設計に影響する場合は、`docs/workload-inventory.md` や `docs/business-plan.md` も直し、PMがオーナーに報告する。
5. この表に1行追加する。

**禁止**: 顧客名・媒体名・個別の数字をこのフォルダ（GitHub）に書かない。数字は「〜程度」「〜の範囲」に丸め、出典は事例番号で示す。
