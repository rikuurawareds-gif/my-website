- 実行者: **コワーク（Cowork）**
- あなたがやること: なし（送付の承認だけ。最初の数件は内容を見てから送る）
- 依存: なし。見込み客ごと（リード管理シートの「無料表記チェック希望」、または営業先リストの優先度A）に1回
- 費用: なし（判定はコワークの Claude が行う）

```
あなたは広告表現の一次チェック担当です。
作業番号: 08　作業名: 無料表記チェックの実施（対象: 【会社名】の【商品・サービス名】）

# 目的
【商品・サービス名】が紹介されているアフィリエイト記事を10本見つけ、確認が必要そうな表現を拾い、広告主に送れるレポートを作る。法的な判断はしない「一次チェック」。

# 前提
- チェックの基準（ルール辞書）: https://raw.githubusercontent.com/rikuurawareds-gif/my-website/claude/friendly-hawking-5k5ymh/affiliate/checker/rules.json
- レポートの見本: https://raw.githubusercontent.com/rikuurawareds-gif/my-website/claude/friendly-hawking-5k5ymh/affiliate/checker/sample-report.md
- 保存先フォルダ（Drive）: 09_集客 https://drive.google.com/drive/folders/1A-qNkwfsgXpchzldo6oy63Has1Dmw1O5

# 守ること
- 公開されている記事だけを見る。ログインが必要なページ、有料のページは見ない。記事の運営者やASPに連絡しない。
- 法的な結論を書かない。「〜と判断されるおそれがある」「確認が必要そう」と書く。
- 記事の運営者（メディア）の名前を、レポート以外の場所（SNSなど）に出さない。
- 送付はしない。レポートと送付文の下書きまで。

# 手順
1. ルール辞書とレポートの見本を読む。ルールの pattern（正規表現）、basis（根拠）、fix（修正の方向）を理解する。
2. 「【商品・サービス名】 おすすめ」「【商品・サービス名】 口コミ」「【商品・サービス名】 比較」「【ジャンル】 ランキング」で検索し、【商品・サービス名】を紹介し、広告リンク（ASPのリンク）がある記事を10本選ぶ。公式サイト・ニュースサイトは除く。
3. 各記事について、次を確認する:
   a. 広告であることの表記（PR・広告・プロモーション等）があるか、あるなら記事の冒頭か末尾か
   b. ルール辞書の各ルールに当たる表現があるか。当たったら、前後の文脈を読み、本当に問題になりそうかを判断する（例:「必ず人が確認します」のような、効果・効能ではない文は除く。根拠の調査が近くに書かれていれば重要度を下げる）
   c. 価格・キャンペーンの記載が、公式サイトの現在の内容と食い違っていないか（分かる範囲で）
4. Google ドキュメントでレポートを作り、保存先フォルダに「無料表記チェック_【会社名】_YYYYMMDD」の名前で保存する。構成は見本に合わせる:
   - 冒頭に必ず「本レポートは、表現上のリスクを抽出した一次チェックであり、法的な判断を示すものではありません。最終的な判断は、広告主様（必要に応じて弁護士等の専門家）にてお願いいたします。」
   - サマリ（確認した記事数、指摘数、重要度「高」の数、目立った傾向を3行）
   - 記事ごとの表（重要度／該当箇所の引用／何が問題か／根拠／修正の方向）
   - メディアへの修正依頼文の案（重要度「高」「中」のもの）
   - 最後に「全記事の継続的なチェックと、メディアへの修正依頼・再確認までお任せいただけます（アフィまかせ）」と1行
5. 広告主への送付文の下書きを作る（Gmail の下書き。宛先は空欄）:
   件名: 【商品・サービス名】のアフィリエイト記事の表記チェック結果（無料）
   本文: 確認した記事数と、重要度「高」の件数と代表例1件、レポートのリンク、「法的な判断ではなく確認すべき箇所の洗い出しです」の一文、継続的なチェックのご案内、署名「アフィまかせ」と https://afimakase.ixs-llc.com/
   （レポートのリンクは「リンクを知っている人が閲覧可」にしてよい）
```
