# SEO・AIO のコンテンツ計画

## 方針
- 読者: **広告主（マーケ担当・上長）とアフィリエイト代理店**。メディア運営者（アフィリエイター）向けの記事は書かない（顧客ではないため）
- 目的: 「アフィリエイト 運用代行」などの検索と、AI の回答（Google の AI による概要、ChatGPT、Perplexity など）で、アフィまかせが情報源として引用されること → 工数診断・無料チェックへの申込
- 強み: オーナーの実務の知見（`../knowledge/`）。一般論の記事は多いので、**実務の数字と手順** で差をつける。ただし顧客名・媒体名・個別の数字は出さない

## AI に引用されやすい書き方（AIO）
1. **冒頭の段落で結論を言い切る**（ビルド時に「結論」ボックスになる）。定義・計算式・数字を最初に
2. 見出しは、読者が実際に検索・質問する言葉にする（「〜とは」「〜のやり方」「〜の費用」）
3. **表** で比較・手順をまとめる。**計算式と計算例** を入れる
4. 「## よくある質問」に3〜5問。FAQ の構造化データになる
5. 法令・相場は **公的な一次情報か、出典のある情報にリンク** する。古くなる数字には時点を書く
6. 公開日・更新日・運営者を明記。半年に1回見直して更新日を上げる
7. サイト全体: `robots.txt`（AI のクローラーを許可）、`sitemap.xml`、`llms.txt`（AI 向けのサイト案内）、LP の構造化データ（組織・サービスと料金・FAQ）はビルドで自動更新

## 書き方の手順
1. `site/content/<英語のslug>.md` を書く（形式は `site/build.py` の先頭）
2. `python3 site/build.py` → `site/column/` と sitemap・llms.txt が更新される
3. `python3 checker/check.py --html site/column/<slug>/index.html` で自社の表現を確認（法令の解説で例として挙げた表現は誤検知なので問題なし）
4. `compliance-reviewer`（社内法務チェック）で原稿を確認し、「要修正」を直す
5. 自分の原稿と build の出力だけを `git add <パス>` で記録 → `git pull --rebase` → push で自動公開。`docs/workstreams.md` の「受け渡し」に1行書く（X での紹介は PM が行う。投稿キューは触らない）

工数削減の記事群の設計と実行計画: `specs/2026-11-28-kosu-cluster-design.md`、`specs/2026-11-28-kosu-cluster-plan.md`

## ペース
- SEO・AIO 担当が書き、自社チェックを通ったものから公開する（**週2本は下限**）。公開ごとのオーナー確認はなし（2026-11-28 オーナーが委任）
- 「アフィリエイト 代理店 料金」は新しい記事を作らず、`affiliate-unyo-daiko` で受け止める（自分の記事どうしで同じ言葉を食い合わないため）
- 「おすすめ・比較」系は、工数削減の記事群がそろってから「選び方」の形で書く
- 3か月後に、検索での表示回数・クリック（Search Console）と、記事から診断への流れ（GA4: `col-` で始まるページ）を見て、伸びている柱を増やす
