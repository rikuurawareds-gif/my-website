# 設計: コラム「工数削減」の記事群（SEO・AIO）

作成: 2026-11-28（SEO・AIO 担当）／ 状態: 確定（2026-11-28 オーナーが「SEO・AIO の判断はすべて担当に任せる。確認はゼロでよい。クリティカルなもの以外は質問しない」と決定）

## 1. 目的と、なぜやるか
- 広告主のアフィリエイト担当者が、検索や AI（ChatGPT・Google の AI による概要・Perplexity など）で「アフィリエイトの工数を減らしたい」と調べたときに、アフィまかせのコラムが答えとして出る・引用されるようにする。
- 読んだ人に **無料の工数診断**（LP の `/#diagnosis`）→ 相談・申し込みへ進んでもらう。最終ゴールはアフィまかせへの申し込み（オーナー）。
- 「工数」を軸にする理由: オーナーの見立てで、担当者のいちばんの悩みが工数だから。悩みとして挙がったのは、数多くの ASP・メディアとの掲載のやりとり、表記チェック、単価の管理、成果承認、請求の作業（オーナー）。サービスの訴求（「まるごと手離れ」）とも、入口の工数診断とも話がつながる。

## 2. 読者
- 広告主のアフィリエイト担当者（マーケ担当・その上長）。主な層は媒体費 月30〜100万円、担当者の運用工数は月20時間ほど（`knowledge/owner-insights.md`）。
- 代理店は今回の記事群の主な読者にしない（代理店向けは計画の24番で別に書く）。

## 3. 狙う検索・質問（オーナーの挙げた言葉が起点）
- 検索: 「アフィリエイト 工数 削減」「アフィリエイト 運用 おすすめ」「アフィリエイト 代理店 料金」など
- AI への質問の形: 「アフィリエイトの工数がかかって困っている。短縮する方法はない？」
- 「おすすめ・比較」系（代理店のおすすめ、成果報酬型広告のおすすめ）は今回やらない（6. 参照）

## 4. ゴール・やらないこと・失敗とみなすこと
**ゴール**
- 工数削減のまとめ記事（ハブ）1本と、作業ごとの記事4〜5本を公開し、互いにリンクでつなぐ
- どの記事も冒頭で質問に言い切って答え、AI が引用しやすい形にする（`marketing/content-plan.md` の「AI に引用されやすい書き方」に従う）

**やらないこと**
- アフィリエイター（メディア運営者）向けの記事
- 他社名を挙げた比較・ランキング記事
- 記事テンプレート・デザイン・LP の変更（PM の持ち物。必要なら PM に提案）
- ixs-llc.com（会社サイト）の変更（別リポジトリ。リンクを張る依頼だけ PM に出す）

**失敗とみなすこと**（記事が公開できても、これに当たれば失敗）
- 一般論だけで、ほかのサイトと同じことしか書いていない
- 顧客名・媒体名・個別の数字が読み取れる
- 「必ず半分になる」など、根拠のない言い切り（自社の広告にあたるため、景品表示法上の誇大な表示になりうる）
- 法律について最終的な判断をしているように読める

## 5. 制約
- 担当範囲: 書いてよいのは `site/content/*.md` と `marketing/content-plan.md`（と、この設計書）。`build.py` は実行だけ（`docs/workstreams.md`）
- 記事の形式は `site/build.py` の先頭のとおり。CTA（工数診断への誘導）はテンプレートが本文の途中と末尾に自動で入れる。関連記事の自動表示はないので、記事どうしのリンクは本文に手で書く
- 公開前に `checker/check.py` を通す。記録は `git add <パス>` だけ、push 前に `git pull --rebase`
- リポジトリは公開。事例は伏せて一般化する（`affiliate/CLAUDE.md`）
- ペースは週2本（コラム計画）

## 8. ハブ記事（1）の中身
- **冒頭の結論**: 主な作業と月の時間の目安を出し、「なくす → 自動化する → 任せる」の順で減らす、と言い切る
- **作業別の表**: 作業、月の時間の目安、減らし方、詳しい記事へのリンク
- **数字の出し方**（SEO・AIO の判断）:
  - 実データは `knowledge/workload-benchmarks.md` の事例001 を使う。ただし **業種は出さず**、「ASP・メディア約20社と取引する、運用が重めの広告主の一例」として、作業ごとの時間の **比率と大きい順** を中心に見せる
  - 「移管後 約10時間」は、**人の代理店に任せた場合の例であり、アフィまかせの実績ではない** と本文に明記する（自社の効果に見せない）
  - あわせて「多くの広告主はもっと少なく、月20時間ほど」というオーナーの見立てを書き、80時間が標準だと誤解させない
  - `docs/workload-inventory.md` の時間は仮の数字なので、記事には「目安」として幅で書く
- **「なくす」の例**: 全件承認型の契約で承認作業そのものをなくす、など
- **内製か外注かの判断**: 短い節を置き、運用代行とは（`affiliate-unyo-daiko`）へリンクする
- **自社への触れ方**（SEO・AIO の判断）: 本文は中立な解説にする。料金の比較（「20時間を月5万円で」など）は本文に書かない（料金の表示は PM の持ち物で、比べ方によっては景品表示法上の論点が出るため）。自社への誘導は、テンプレートの CTA と、「任せる」の節の最後の1文（サービスページへのリンク）だけにする
- **よくある質問**: 3〜5問。AI への質問の形にそろえる（例: 「アフィリエイトの運用には月何時間かかる？」）

## 9. 決まっていること
**オーナー**
- 記事の置き場所はアフィまかせのコラム（`afimakase.ixs-llc.com/column/`）。IXS の会社サイトには置かない
- 進め方は A
- 読者の悩みと狙う言葉は 1・3 のとおり
- SEO・AIO の判断は担当に任せる。公開ごとのオーナー確認はなし

**SEO・AIO の判断（オーナーの委任による）**
- **ノウハウの出し方**: 基本は「何を見るか・なぜそうするか」の考え方まで。作業ごとの時間などの **数字ははっきり出す**。ASP への連絡の型、媒体調査の具体的な手順、レポートの要因分解の型そのもの（テンプレート）は出さず、「診断・相談で」と残す。理由: 数字は引用されやすく、「自社はどうか」→ 工数診断につながる。手順まで出すと読んで満足されて終わる（`knowledge/owner-insights.md`）
- **公開の流れ**: `check.py` と `compliance-reviewer` を通したら、SEO・AIO 担当が公開する。公開したら `docs/workstreams.md` の「受け渡し」に書き、PM 経由でオーナーに報告する
  - `compliance-reviewer` が「要修正」とした点は直してから公開する
  - 法律の解釈に迷うもの、他社名・顧客名に触れるものは公開せず PM に回す（クリティカル扱い）

## 10. 作る側に任せること
- タイトル・見出し・本文の言い回し、よくある質問の選び方
- 各記事の長さ（目安は既存の記事と同じくらい）
- 出典にする公的な資料の選び方
- 2〜6 の細かい順番の入れ替え（公開済みの記事とのつながりを見て）
