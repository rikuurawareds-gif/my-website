# M2 掲載監視（表記チェック）

## 何を納品するか
提携メディアの記事から、ステマ規制・景品表示法・薬機法などに抵触しそうな表現を定期的に拾い、**修正指示まで書いたレポート**を出す。法的な最終判断はしない「一次チェック」。

## 流れ
1. **対象の登録**: 顧客から「提携メディア台帳」（Drive の顧客フォルダ）をもらう。ASP の提携メディア一覧CSVを置いてもらえば自動で台帳化する。
2. **記事の発見**: メディアのサイト内で、顧客の商品名・ブランド名・広告リンクを含む記事を探す（サイトマップ → 本文検索）。
3. **取得**: 公開ページだけを取得する。robots.txt を守り、同じサイトへのアクセスは数秒間隔にする。前回から変わっていない記事は飛ばす。
4. **チェック**（2段階）
   - ルール辞書: 「No.1」「最安」「必ず痩せる」などの危険表現、PR表記の有無と位置、価格・キャンペーンの記載を機械的に抽出する。
   - Claude: 辞書に当たった箇所と記事全体の文脈から、リスクの程度、根拠（どの法令・ガイドラインのどの考え方か）、**メディアにそのまま送れる修正依頼文**を作る。
5. **レポート**: 顧客フォルダ `03_表記チェックレポート` に保存し、Chatwork（または メール）で要約を送る。
6. **運用代行プランの場合**: 修正依頼をメディアに送り、修正されたかを再チェックするところまで行う。

## レポートの形
| 重要度 | メディア | 記事URL | 該当箇所 | 何が問題か | 根拠 | 修正案 | 状態 |
|---|---|---|---|---|---|---|---|
| 高: PR表記なし、効果の断定など / 中 / 低 | | | 原文の引用 | | 景表法（優良誤認）など | | 未対応・依頼済・修正済 |

レポートの冒頭に毎回入れる文: 「本レポートは表現上のリスクを機械的・統計的に抽出した一次チェックであり、法的な判断を示すものではありません。」

## 顧客ごとのレギュレーション
広告主は独自の表現ルール（NGワード、必ず入れる注意書き、使ってよい実績数値）を持っていることが多い。`04_契約・レギュレーション` に置いてもらい、チェックに加える。これが他社との差になる。

## 品質の測り方
- 毎月、指摘のサンプルを人が確認し、誤検知（問題ないのに指摘した）と見落とし（後から見つかった）を記録する。
- 顧客が「対応不要」とした指摘は理由を残し、ルール辞書とプロンプトの改善に回す。

| スタンダード | 〜100 | 隔週 | 5万円 |

## 集客の入口
「無料で10記事チェック」を LP に置く。商品名を入力すると、上位メディアの記事をチェックしてサンプルレポートを返す。
