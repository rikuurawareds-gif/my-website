# 商品3: 運用代行（Chatwork常駐）

## 姿
こちらで作った運用担当アカウントを、顧客の Chatwork に入れてもらう。そのアカウントが ASP 担当・メディアとのやり取りを受け持ち、顧客にはレポートやまとめを送る。

```
ASP担当 ─┐
メディア ─┼─ Chatwork（顧客が作ったルーム） ─ 運用担当アカウント ─ 受信サーバー ─ Claude
顧客担当 ─┘                                                     │
                                         承認待ちの下書き → 社内の承認ルーム（オーナー/運用者）
```

## できるようにすること
| 業務 | 内容 |
|---|---|
| 立ち上げ支援 | ASP選定、報酬形態（定額・定率・特単）の設計、計測（成果タグ・ポストバック）の確認、プログラム規約・承認基準の作成 |
| ASP担当とのやり取り | 案件情報の更新依頼、特集・メルマガ枠の相談、成果の確認 |
| メディアとのやり取り | 新規提携の挨拶、掲載依頼、特単の提案、表記の修正依頼 |
| 成果承認の補助 | 承認基準に沿って承認・否認の候補を出す（最終判断は顧客） |
| 顧客への報告 | 週次のまとめ、月次レポート、判断が必要なことの依頼 |

## AIに任せる範囲（顧客ごとに設定）
| レベル | 動き | 使う場面 |
|---|---|---|
| L0 | 下書きだけ作る。人が全件承認して送る | 導入直後、すべての顧客の初期状態 |
| L1 | 定型連絡（お礼、受領、日程調整、資料送付）は自動送信。それ以外は承認 | 1か月問題なく回ったら |
| L2 | 表記の修正依頼、掲載依頼も自動送信。条件・金額が絡むものは承認 | 顧客の同意がある場合 |
| L3 | 決められた範囲内の特単提案も自動 | 長く取引のある顧客のみ |

次のものは **どのレベルでも人の承認が必要**:
- 金額・報酬条件・契約に関わる内容
- 成果の否認、提携の解除
- 苦情・トラブル・法的な話題
- AIの確信度が低いもの（返事の意図が読めない、前例がない）

## 名乗り方
アカウントは「〇〇（サービス名）運用担当」とし、プロフィールに「AIアシスタントを使って対応しています。重要事項は担当者が確認します」と書く。相手が後から知って信頼を失うのを避けるため。

## 技術メモ（実装前に確認すること）
- Chatwork API（v2）でメッセージの取得・送信ができる。Webhook でメンションやルームのメッセージを受け取れる。プランごとのAPI利用条件、Webhookの対象範囲、レート制限は実装前に公式ドキュメントで確かめる。
- 顧客側が Chatwork のビジネスプランで外部ユーザーの招待やAPI利用を制限している場合がある。導入時に確認する。
- 受信サーバーは常時動いている必要がある（Claude Code のセッションは常駐しないため）。構成は `../architecture.md`。
