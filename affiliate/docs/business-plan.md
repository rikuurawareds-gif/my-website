# 事業計画 — アフィリエイト運用支援サービス

## 1. 誰の、どんな困りごとを解くか

| 顧客 | 困りごと | 払う理由 |
|---|---|---|
| A. これから始める広告主 | 何から手をつけるか、どのASP・代理店に声をかけるか、報酬形態・計測・規約・承認作業が分からない | 立ち上げの失敗（ASP選定ミス、計測漏れ、承認基準の不備）を避けたい |
| B. すでに運用中の広告主 | ASP担当・メディアとの日々のやり取り、新規メディア対応、成果承認、表記チェックに工数がかかる | 担当者1人分の工数を月10〜20万円で外に出したい |
| C. メディア（アフィリエイター） | 複数ASPの報酬改定・案件終了・新規案件を追いきれない | 取りこぼしと機会損失を減らしたい |

特に効くのは **ステマ規制の責任主体は広告主** という点。外部メディアの記事は広告主が自分では管理しきれないリスクなので、表記チェックにお金を払う理由がはっきりしている。

## 0. 最新の方針（2026-11-26）
料金・顧客像は `decisions.md` と `../knowledge/owner-insights.md` が最新。主な顧客は媒体費 月30〜100万円の広告主（運用プラン 月5万円）と、アフィリエイト代理店（1アカウント月5万円）。以下の価格仮説は古い。

## 2. 売り方: 「アフィリエイトの運用を完全に手離れさせる」

商品を機能ごとに分けて売らない。**広告主のアフィリエイト工数を丸ごと引き受けるパッケージ1つ**を売る。中身は工数の棚卸し（`workload-inventory.md`）の全作業で、裏側はモジュール M1〜M9 で自動化していく。

| 商品 | 対象 | 価格仮説 | 中身 |
|---|---|---|---|
| **完全手離れプラン**（本命） | A・B | 媒体費の10%前後（最低月額15万円程度）＋初期費用。媒体費が小さい顧客は最低月額、大きい顧客は料率で | 立ち上げ（A1〜A8）と、定常・月次・突発の全作業（B・C・D）。顧客がすることは週1回の確認と、金額・契約の承認だけ |
| 入口: 無料のアフィリエイト工数診断 | A・B | 無料 | 今の作業を答えると、月に何時間・いくら分の工数がかかっていて、何時間手離れできるかが分かる |
| 入口: 無料の表記チェック（10記事） | B | 無料 | M2 の出力そのもの。リスクが見えると、手離れの必要性が伝わりやすい |
| メディア向け監視 | C | 月1,000〜3,000円 | 別商品。メディアとのつながりが M5（メディア開拓）の資産になる |

価格は仮説。実際の代理店提案では「媒体費の10%前後」か「作業時間×人月単価」の2方式だった（`knowledge/proposal-playbook.md`）。`business-strategist` が相場とASPの代理店手数料を調べて検証する。

訴求の軸は「**件数の増加と工数の削減の両立**」。工数削減だけでなく、成果が伸びることを数字で示す（M10 改善エンジン）。

### メディア向け監視が本命を強くする
メディア向けサービスの利用者は、そのまま **広告主の新規提携先の候補** になる。手離れプランで約束する「新規メディアの開拓」が、メディア側の会員数に比例して強くなる。

## 3. 立ち上げの順番（推奨）

1. **最初から「完全手離れ」で売る。** ただし最初の3〜5社は、AIの下書きをオーナーが承認して回す（人手で引き受ける部分が残る）。社数は人手で回せる範囲に絞る。
2. **作業を全部記録する。** 作業番号（B2など）と時間を残し、時間がかかっている順に自動化する。
3. 自動化の順番の初期案は `workload-inventory.md` の「優先順位」。M1 統合受信箱 → M2 掲載監視 → M8 レポート → M4 提携審査 → M3 成果承認 …
4. 自動化が進んだ分だけ、受け入れる社数を増やす。

## 4. 前提とするルール（ここを外すとサービスが成立しない）

- **法的判断はしない**: 表記チェックは「リスクがありそうな表現の一次抽出と修正案の提示」。最終判断は顧客（必要なら顧客の弁護士）。利用規約・レポートの両方に明記する。報酬を得て個別の法律判断をすると弁護士法72条（非弁行為）に触れるおそれがあるため。
- **AIの送信は段階的に任せる**: ASP・メディア宛ての文章は、最初は全件を人が承認してから送る。顧客ごとに自律レベルを上げる（`services/chatwork-ops.md` の L0〜L3）。
- **権限は契約で決める**: 顧客の代わりに連絡してよい範囲（定型連絡、条件交渉、承認・否認の判断）を業務委託契約に書く。
- **顧客データを混ぜない**: 顧客ごとに Drive フォルダ・Chatwork ルーム・データを分ける。秘密保持契約を結ぶ。
- **クロールは行儀よく**: 公開記事だけを対象にし、robots.txt と頻度制限を守る。ASP管理画面へのログインやスクレイピングはしない。

|---|---|
| 集客 | サービスLPの問い合わせ数、無料表記チェックの申込数 |

| 工数 | 顧客1社あたりのこちらの人手作業時間（目標: 最初は月10時間以下、自動化が進んだら月2時間以下）、顧客側の作業時間（目標: 月1時間以下） |
